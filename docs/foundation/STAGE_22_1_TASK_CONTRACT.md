## Purpose

Shift SongChart from horizontal architecture expansion to production-oriented vertical closure. Stage 22.1 makes subsystem intersections first-class machine authority, defines the first golden provider-to-public-song flow, and proves that provider evidence, canonical identity, chart projection, public read paths, correction propagation and release verification compose through explicit owners.

## Product outcome

A real provider-backed Recording can retain traceable evidence, resolve through governed canonical identity, produce a provenance-first chart projection, appear through public/search surfaces, and propagate governed corrections without direct manual cross-system database repair.

## Invariants

1. Component existence is not treated as flow closure.
2. Every critical intersection has explicit implementation/verification evidence.
3. Provider evidence remains provenance; ingestion success never becomes canonical identity by itself.
4. Canonical mutation remains governed by admission/authorization/audit owners.
5. Chart rows require canonical identity and reproducible calculation/input provenance.
6. Public chart/search/entity projections agree on canonical identity.
7. Golden replay is idempotent at observation/canonical projection boundaries.
8. Semantic canonical corrections propagate through governed listeners/jobs rather than manual repair.
9. Existing impact, quality, PostgreSQL, browser, frontend, candidate and canonical verification remain the verification owners; no duplicate golden verifier was introduced.
10. Generated project/development state remains projection-only and is regenerated by the governed PREPARE flow.
